## 📖 About This Repository

Welcome to my **C++ Problem-Solving Journey**! This repository documents my progress as I rebuild my C++ foundations and develop the ability to solve unfamiliar programming problems independently.

## 🧠 Learning Philosophy

> *"Every problem is an opportunity to understand a concept more deeply."*

My structured problem-solving workflow follows an 8-step blueprint:

1.  **Understand:** Explain the problem constraints and objectives in my own words.
2.  **Analyze:** Formally identify inputs, outputs, data ranges, and hidden edge cases.
3.  **Trace:** Manually execute and dry-run a baseline example using pen and paper.
4.  **Design:** Develop a high-level algorithm using plain language or structured pseudocode.
5.  **Implement:** Translate the designed algorithm into clean, idiomatic C++.
6.  **Test:** Validate implementation against normal, boundary, and explicitly invalid inputs.
7.  **Analyze:** Evaluate functional correctness along with **Time** and **Space Complexity** (O(N) notation).
8.  **Improve:** Refactor the codebase for performance and readability, documenting key takeaways.

## 🛠️ Engineering Principles

I hold myself accountable to these strict code hygiene rules:

*   **Self-Documenting Code:** Meaningful variable/function nomenclature without bloated inline comments.
*   **Single Responsibility Principle:** Small, predictable, isolated functions focusing on a single task.
*   **Defensive Design:** Explicit boundary validation and strict runtime error checks.
*   **Granular Versioning:** Small, incremental commits governed by expressive, declarative messages.
*   **Correctness Over Optimization:** Striving for elegant, functionally correct paths before adjusting code for performance.
*   **Fail Openly:** Embracing logic flaws transparently to log lessons within reflections.
